# Разработка Translateer

## Как устроено

Translateer — bash-скрипт [`translateer`](translateer) поверх готовых утилит и окно перевода [`translateer-window`](translateer-window) на Python и GTK 4:

| Утилита | Пакет | Зачем |
|---|---|---|
| `wl-paste` | wl-clipboard | читает выделенный текст (primary selection) или буфер обмена |
| `trans` | translate-shell | переводит |
| `zenity` | zenity | диалоги: выбор направления, ввод текста |
| `translateer-window` | python3-gi, gir1.2-gtk-4.0, gir1.2-adw-1 | окно перевода |
| `pgrep`, `flock` | procps, util-linux | закрывают диалоги предыдущего запуска |
| `notify-send` | libnotify-bin | уведомление, когда нечего переводить |
| `gsettings` | (есть в GNOME) | назначает горячие клавиши |

Режимы запуска:

- `translateer` — перевод выделенного текста. Так программу вызывает Ctrl+Alt+E.
- `translateer --choose` — то же, но сначала открывается выбор направления. Так программу вызывает Ctrl+Alt+Shift+E.
- `translateer --input` — окно для ввода текста. Так программа запускается из меню (`Exec` в `.desktop`-файле); при первом запуске в этом режиме вызывается `setup_hotkeys`.

### Горячие клавиши

Пакет сам клавиши не назначает: скрипты установки `.deb` работают от root и не видят настроек пользователя. Поэтому их назначает функция `setup_hotkeys` — один раз для каждого пользователя (флаг `~/.config/translateer/hotkeys-configured`). Список клавиш — массив `hotkeys` в начале скрипта.

1. Если в системе нет схемы `org.gnome.settings-daemon.plugins.media-keys` (не GNOME) — показывает инструкцию для ручной настройки.
2. Для каждого сочетания `hotkey_taken` ищет его во всех схемах (`gsettings list-recursively`) и в пользовательских настройках (`dconf dump /`), не обращая внимания на порядок модификаторов и регистр (`<Alt><Primary>E` = `<Control><Alt>e`). Занятые сочетания не трогает.
3. Свободные добавляет как особые комбинации по путям `/org/gnome/settings-daemon/plugins/media-keys/custom-keybindings/translateer/` и `.../translateer-choose/`.
4. Сообщает, что назначено, а что нет и почему.

### Направление перевода

Направление спрашивается один раз для каждого языка текста и хранится в `~/.config/translateer/targets` строками вида `ru=en`. Меню выбора открывается, когда для языка текста направления ещё нет, при `--choose` и по кнопке «Другое направление»; любой выбор в меню запоминается. Обратный перевод выбор не меняет.

Язык текста угадывается по буквам: `і ї є ґ` → украинский, `ы э ъ ё` → русский, другая кириллица → тот из двух языков, для которого направление уже выбрано (иначе русский), остальное → английский. В шаблонах `grep` буквы перечислены явно: диапазон `[А-Я]` в локали `C.UTF-8` GNU grep считает ошибкой (`Invalid collation character`).

### Одно окно

Каждое нажатие горячей клавиши запускает скрипт заново. Чтобы окна не копились:

- **Окно перевода** — `Gtk.Application` с `application_id` `io.github.anrysys.Translateer`. Скрипт в конце делает `exec translateer-window НАПРАВЛЕНИЕ ПРЕДУПРЕЖДЕНИЕ ТЕКСТ`; если окно уже открыто, второй экземпляр передаёт ему аргументы по D-Bus и сразу завершается. Окно не пересоздаётся, поэтому остаётся на месте и того же размера: на Wayland программа не может ни узнать, ни задать положение своего окна, так что место сохраняется, только пока окно открыто. Размер при закрытии записывается в `~/.config/translateer/window-size`.
- **Диалоги zenity** (выбор направления, ввод текста) — `take_over` хранит PID последнего запуска в `$XDG_RUNTIME_DIR/translateer-$UID.pid` и закрывает диалоги предыдущего запуска вместе со всеми его потомками. Окно перевода она не трогает: после `exec` в этом PID уже python, а не bash. Старые диалоги закрываются только после того, как прочитано выделение, — выделенный в них текст не теряется.

Кнопки окна перевода (обратный перевод, другое направление, повтор) работают внутри `translateer-window`; выбор направления оно записывает в тот же файл `targets`.

### Защита от ошибок

Программа следует принципам Poka-yoke — не даёт пользователю навредить себе и объясняет, почему что-то не сделала:

- **Только чтение.** Выделение и буфер обмена не изменяются; файл `targets` записывается через временный файл и `mv`, поэтому не остаётся полузаписанным.
- **Длинный текст.** На тексте длиннее ~2500 символов кириллицы translate-shell молча возвращает пустой перевод. Поэтому текст длиннее `max_chars` (2000) обрезается по границе слова, а над переводом выводится предупреждение.
- **Ошибка перевода.** Сообщение об ошибке не переводится обратно: кнопка «⇄ Обратный перевод» превращается в «↻ Повторить».
- **Пустое выделение** (в том числе из одних пробелов) — уведомление вместо пустого окна.
- **Испорченный `targets`.** Строки с неизвестными языками или переводом «сам в себя» пропускаются — направление просто спросится заново.
- **Чужие сочетания клавиш** не перезаписываются (см. выше).

## Структура

```
translateer                                      скрипт программы → /usr/bin/translateer
translateer-window                               окно перевода → /usr/libexec/translateer/translateer-window
data/translateer.svg                             иконка; из неё при сборке делаются PNG 16–256 px
data/translateer.desktop                         ярлык в меню приложений
data/io.github.anrysys.Translateer.metainfo.xml  карточка AppStream для App Center и других магазинов
changelog                                        журнал изменений в формате Debian
build-deb.sh                                     сборка .deb
```

## Сборка

Нужны `dpkg-deb` (есть в любой Ubuntu/Debian), `rsvg-convert` (пакет `librsvg2-bin`) и `gzip`.

```bash
./build-deb.sh
```

Пакет появится в `dist/translateer_<версия>_all.deb`, дерево файлов пакета — в `build/`.

## Проверка

```bash
bash -n translateer                                                   # синтаксис
python3 -m py_compile translateer-window                              # синтаксис окна
./translateer                                                         # запуск без установки
desktop-file-validate data/translateer.desktop                        # пакет desktop-file-utils
appstreamcli validate data/io.github.anrysys.Translateer.metainfo.xml # пакет appstream
appstreamcli validate-tree build/translateer_*_all                    # после сборки: .desktop + иконки + metainfo
apt-get install -s ./dist/translateer_*_all.deb                       # зависимости, без установки
```

Проверяйте скрипт в настоящем bash, а не в интерактивной оболочке: в zsh с плагинами `grep` бывает функцией-обёрткой и ведёт себя иначе, чем GNU grep, которым пользуется скрипт.

Без установки горячие клавиши работать не будут: они вызывают команду `translateer` из `PATH`. Чтобы проверить первый запуск «с нуля», удалите `~/.config/translateer/` и особые комбинации Translateer в настройках клавиатуры.

## Выпуск новой версии

1. Поднимите `version` в `build-deb.sh`.
2. Добавьте запись в начало `changelog` (формат Debian: `dch` из пакета `devscripts` или вручную).
3. Добавьте `<release>` в `data/io.github.anrysys.Translateer.metainfo.xml`.
4. Соберите пакет и опубликуйте релиз:

   ```bash
   ./build-deb.sh
   git commit -am "Translateer 1.2.0" && git tag v1.2.0 && git push --follow-tags
   gh release create v1.2.0 dist/translateer_1.2.0_all.deb --title "Translateer 1.2.0" --notes "Что изменилось"
   ```
